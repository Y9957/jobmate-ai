# 라벨 기준표

평가 데이터(`evals/cases/*.json`)의 정답 라벨은 아래 규칙으로 붙인다.
규칙이 바뀌면 이 문서와 라벨을 함께 고치고, 결과 파일에 기록된 데이터 버전을 올린다.

## 데이터 분할

| split | 내용 | 용도 |
|---|---|---|
| `easy` | 짧고 깔끔한 이력서 6개 × 공고 2개 | 회귀 점검. 첫 측정에서 검증 없이도 만점이 나와 변별력이 없음을 확인 |
| `dev` | 1쪽 분량의 현실적인 이력서, 새 함정 유형 포함 | 프롬프트·로직을 고칠 때 **이것만** 보고 고친다 |
| `test` | `dev`와 같은 방식으로 만든 별도 케이스 | 프롬프트 버전마다 **한 번만** 실행하고, 보고하는 수치는 이것 |

## 데이터 원칙

- 이력서·공고는 모두 **가상**이다. 실존 인물·회사·공고 문장을 쓰지 않는다.
- 연락처는 넣지 않는다(마스킹 동작은 단위 테스트에서 따로 검증).
- 각 케이스는 이력서 1개 + 공고 요구조건 목록 1개. 요구조건은 공고 파싱 결과가 아니라 **정답으로 고정**된 목록이다
  (공고 파싱 품질과 매칭 품질을 섞어서 재지 않기 위해).

## 판정 라벨 (`gold`)

| 라벨 | 기준 |
|---|---|
| `met` | 이력서 **문장 하나만 읽고** 요구조건 충족을 확인할 수 있다 |
| `not_met` | 그 외 전부 — 언급이 없음, 비슷하지만 다른 기술, 연수·학위 부족, **정보 자체가 없음** |

- 시스템의 `insufficient`(근거 부족)는 채점할 때 `not_met`과 같게 본다.
  "확인되지 않으면 충족이 아니다"가 이 서비스의 원칙이기 때문이다.
- 이력서의 **기술 목록**에 있는 기술은 "사용 경험·능력" 요구조건의 근거로 인정한다.
  단, 기간·수준(예: 3년 이상, 대규모 운영)은 기술 목록만으로 인정하지 않는다.
- 경력 연수는 이력서에 적힌 기간을 그대로 쓴다. 인턴 기간도 경력 기간에 포함해 계산하되, 요구조건이 "실무 경력"이면 적힌 기간 합계로 판단한다.

## 근거 라벨 (`evidence`)

- `met` 항목에는 근거가 될 수 있는 **이력서 줄을 원문 그대로** 모두 적는다(1개 이상).
- 시스템의 인용문은 정규화(공백·글머리 기호·전각 문자) 후 어떤 근거 줄과 **포함 관계**(인용문 ⊂ 근거 줄, 또는 근거 줄 ⊂ 인용문)이면 올바른 근거로 본다.
- 모든 근거 줄이 실제로 이력서에 있는지는 테스트(`tests/test_eval_cases.py`)가 확인한다.

## 함정 유형 (`tags`)

| 태그 | 의미 | 예 |
|---|---|---|
| `direct` | 요구조건의 기술·경험이 이력서에 그대로 나옴 | 요구 "React" ↔ "React와 TypeScript로…" |
| `paraphrase` | 같은 것을 다른 말로 표현 | 요구 "관계형 데이터베이스" ↔ "PostgreSQL 인덱스를 설계…" |
| `absent` | 이력서에 아예 없음 | 요구 "Kafka" |
| `adjacent_trap` | 비슷하지만 다른 기술·자격 | Java ↔ JavaScript, Tableau ↔ Power BI, ECS ↔ Kubernetes, ADsP ↔ SQLD |
| `tempting_quote` | 없는 요구조건인데 그럴듯한 문장이 있음 | 요구 "Redis 캐시" ↔ "응답 시간을 30% 줄였습니다" |
| `years` | 경력 연수 조건 (충족·미충족 모두) | 요구 "3년 이상" ↔ "2년" |
| `degree` | 학위·전공 조건 | 요구 "석사 이상" ↔ "학사" |
| `no_info` | 이력서에 해당 정보 자체가 없음 | 학력 항목이 없는 이력서에 "학사 이상" |
| `weak_mention` | 언급은 있지만 본인이 직접 쓴 경험이 아님 — 팀원·외부가 수행, 관심·학습 중, 교육 수료만 | "Spark 클러스터는 데이터 팀이 운영했고…", "[관심 기술] Kafka" |
| `negation` | 도입을 검토했지만 쓰지 않음 | "Kubernetes 도입을 검토했으나 ECS를 선택했습니다" |
| `level_short` | 경험은 있지만 요구 규모·수준에 못 미침 | 요구 "일 100만 건 이상" ↔ "일 평균 5만 건" |

`weak_mention`·`negation`·`level_short`는 정답이 모두 `not_met`이다.
"관심 기술", "학습 중" 목록은 `[기술]` 목록과 달리 사용 경험의 근거로 인정하지 않는다.
교육 과정 수료는 "실무 경험"·"사용 경험"의 근거가 아니다(요구조건이 교육 이수 자체일 때만 근거).

## 라벨 작성·검토

- 1차 라벨: Claude(코드 작성 보조)가 위 규칙으로 작성
- 검토: 저장소 소유자가 케이스별로 확인
- 애매해서 라벨이 갈릴 수 있는 요구조건(예: "CI/CD 경험"에 CI만 있는 경우)은 데이터에 넣지 않거나, 요구조건 문장을 명확하게 바꾼다.
